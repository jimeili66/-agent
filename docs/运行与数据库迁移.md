# 直播电商运营 Agent 项目介绍与异机运行说明

整理日期：2026 年 10 月 30 日

## 项目介绍

本项目面向直播电商和校园模拟直播，提供商品管理、主播话术生成、弹幕问答、模拟订单、工具调用记录和直播复盘。系统包含用户端、管理端和账号管理端，适合课程展示、项目答辩和 Agent 应用学习。

前端使用 React、TypeScript、Vite 和 lucide-react；后端使用 Python、FastAPI 和 Uvicorn；通过 SQLAlchemy、PyMySQL 连接 MySQL，并调用 DeepSeek 生成话术、商品资料草稿和问答回复。模型不可用时保留本地规则作为备用。

## 核心功能

| 模块 | 功能 |
| --- | --- |
| 商品管理 | 商品列表、搜索、新增、删除、图片上传和 AI 辅助填写资料 |
| 直播话术 | 按商品和用户画像生成开场、介绍、促销、互动和收尾内容 |
| 用户直播间 | 浏览商品、发弹幕、咨询 Agent、购物车和模拟下单 |
| 运营工作台 | 查看用户提问、订单、Agent 处理轨迹和工具日志 |
| 工具处理 | 优惠计算、库存查询、商品推荐、合规规则检查 |
| 账号管理 | 登录、账号创建、修改密码和密码哈希存储 |
| 复盘报告 | 高频问题、情绪分布、销售统计、转化阻碍和排品建议 |

问答流程是：接收问题 → 获取商品上下文 → 运行相关业务工具 → 模型组织回复 → 保存问答和工具记录。当前角色轨迹由后端代码组织，尚未接入 LangGraph。复盘主要由统计和规则生成。订单为模拟订单，尚未实现真实支付和事务库存扣减。

摄像头目前用于同一浏览器环境中的标签页演示，不具备完整的跨设备音视频直播能力。弹幕和订单主要通过轮询更新。面向公网部署前，还应完善后端业务接口的统一权限校验。

## 源码包内容

源码包保留前后端代码、测试、默认商品和图片、依赖清单、启动脚本、Docker 配置以及环境变量示例。它不包含本机 `.env`、真实数据库备份、个人上传图片、日志、Git 历史、虚拟环境或 `node_modules`。

因此，拿到源码不等于拿到了原电脑的商品、账号和订单数据。运行时需要选择“从默认演示数据开始”或“迁移原有数据”。

## 是否需要租服务器

| 使用方式 | 数据库在哪里 | 是否需要租服务器 |
| --- | --- | --- |
| 对方独立演示或提交作业 | 对方电脑的 MySQL | 不需要 |
| 同一局域网的几个人共用 | 一台持续运行的电脑 | 不一定需要，但要配置网络访问 |
| 不同地点长期共用同一份数据 | 服务器或托管数据库 | 通常需要在线部署环境 |

独立运行后，两台电脑的数据各自保存，不会自动同步。如果只是把项目给老师、同学运行，可以先使用对方本机 MySQL，不必为此购买服务器。

如果以后希望任何地方通过一个网址访问，建议将前端、后端和数据库集中部署。浏览器访问网站，后端在内部连接数据库；不应让浏览器直接连接 MySQL，也不建议为了共享数据把你电脑的 MySQL 端口直接暴露到公网。

## 在另一台电脑从默认数据开始

1. 安装兼容的 Python、Node.js 和 MySQL。前端使用 Vite 7，建议 Node.js 22.12 或更高的兼容版本；后端建议 Python 3.13。
2. 解压源码到固定目录。
3. 在项目根目录安装后端依赖：`python -m pip install -r requirements.txt`。
4. 进入 `frontend`，执行 `npm.cmd ci`，完成后回到根目录。命令适用于 Windows。
5. 在 MySQL 创建空数据库：

```sql
CREATE DATABASE IF NOT EXISTS live_agent
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;
```

6. 将 `.env.example` 复制为 `.env`，填写对方自己的数据库账号和密码：

```env
DATABASE_URL=mysql+pymysql://数据库用户:数据库密码@127.0.0.1:3306/live_agent?charset=utf8mb4
DEEPSEEK_API_KEY=自己的DeepSeek密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

密码如果包含 `@`、`:`、`/`、`#` 等 URL 特殊字符，需要对连接串中的密码做 URL 编码。不使用模型时，可以不设置 `DEEPSEEK_API_KEY`，使用本地备用逻辑。

7. 启动：`python start-project.py`，或双击 `start-project.bat`。
8. 首次连接空库时，代码会创建数据表，并初始化默认商品和管理员。演示前应修改默认管理员密码。

不能为了省事不填 `DATABASE_URL`：缺少它时项目可能使用内存模式，新增数据在后端重启后不能保留。

## 把原有数据库迁移到另一台电脑

需要迁移三类东西：数据库中的记录、磁盘里的上传图片、目标电脑自己的连接配置。源码、数据库备份和图片目录应分别准备。

### 导出原电脑数据库

可以使用 Navicat 的数据库导出功能，选择结构和数据；也可以在安装了 MySQL 客户端的终端使用下列示例命令。命令仅供操作时参考，本次没有执行数据库导出。

```powershell
mysqldump -h 127.0.0.1 -P 3306 -u root -p --single-transaction --default-character-set=utf8mb4 --no-tablespaces --set-gtid-purged=OFF --databases live_agent --result-file=live_agent_backup.sql
```

`-p` 会交互提示输入数据库密码。建议在导出期间暂停项目写入，也不要修改表结构。使用与源数据库兼容的客户端和目标 MySQL 版本，跨大版本迁移需另查兼容性。

Windows PowerShell 下使用 `--result-file`，避免输出重定向带来的编码问题。输出文件名应选未使用的新名称，避免覆盖已有备份。导出的文件可能包含账号密码哈希和业务记录，应只交给确实需要这些数据的人。

### 在目标电脑导入

在目标电脑选择空数据库环境，先导入备份，再启动应用。备份可能带有删除和重建表的语句，不要直接导入对方已有业务库。

可在 Navicat 执行 SQL 文件，或在 MySQL 客户端中执行：

```text
mysql -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4
```

进入 MySQL 提示符后执行，路径使用备份的实际位置：

```sql
SOURCE C:/迁移目录/live_agent_backup.sql;
```

该数据库备份迁移的是 `live_agent` 的业务表，不会迁移 MySQL 服务器自身的 root 密码。目标电脑的 MySQL 账号、权限和密码需要单独配置。应用的 `accounts` 表属于业务数据，导入后会保留原有应用账号及密码哈希。

### 搬迁图片和配置

原电脑上传的图片位于项目的 `backend/uploads/products/`。需要保留这些图片时，另行复制到目标电脑项目的相同目录；仅导入数据库不会复制图片文件。如果数据库图片地址包含原电脑地址，需要按新环境调整。

目标电脑使用自己的 `.env`，不要直接分发原电脑的数据库密码和 API 密钥。DeepSeek 可以配置对方自己的密钥；多人共用服务时，密钥应留在后端。

## 多人共用同一份数据

独立安装适合演示；协作运行应由一个后端统一读写同一数据库。若服务器和 MySQL 在同一环境，可以先部署在同一台服务器，也可使用托管数据库，不强制单独购买数据库服务器。

当前项目的前端和后端主要绑定本机地址，前端 API 地址也以本地环境为默认值。公网或局域网部署需要配置监听地址、API 地址、CORS、HTTPS 和访问控制。摄像头跨设备传输需要另外实现，不能仅靠修改数据库地址解决。

现有 Docker Compose 可以作为环境参考，但仍需核对 DeepSeek 环境变量传递、数据库版本和数据卷。不要把 Compose 数据卷误认为数据库已经随源码打包。

## 常用访问地址

启动成功后，在运行项目的那台电脑上访问：

- 管理端登录：http://127.0.0.1:5173/admin/login
- 用户直播间：http://127.0.0.1:5173/user
- 账号管理：http://127.0.0.1:5173/account
- 后端接口文档：http://127.0.0.1:8000/docs

`127.0.0.1` 始终表示当前访问设备自己。另一台电脑或手机不能直接使用这些地址访问原电脑。
